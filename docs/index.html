RefineKV: Query-Adaptive KV Cache
Compression via Attention-Error Bounds

Abstract

Repeatedly accessing the full key–value (KV) cache is a major bottleneck in long-context language model decoding. We find that small query-specific subsets can accurately approximate full attention, yet their union covers nearly the entire cache, motivating query-adaptive access for the KV cache. A natural approach is to split the KV cache into clusters, using compact representatives for clusters that incur negligible error while expanding the rest to their original KV entries.

We derive a principled selection criterion, an upper bound on attention-output error, which reveals two complementary factors governing the error: importance measures the impact of a cluster, while distortion measures how faithfully the cluster can be represented. Based on this criterion, we propose RefineKV, a decoding-time query-adaptive KV compression method. Experiments on two models and three benchmarks demonstrate that RefineKV retains near-full-attention quality while achieving up to 11.7× speedup in the attention phase and 1.76× faster decoding, establishing a new quality–latency Pareto frontier.

Why Query-adaptive KV Access?

Long-context decoding repeatedly reads a large KV cache, even though each query needs only a small part of it. The difficulty is that the useful subset changes with the query. In the paper’s WikiText-2 study, retaining 90% of attention mass takes 17.6% of KV entries per query, while the union of those subsets covers 96.4% of the cache.

This motivates choosing what to access at each decoding step. RefineKV keeps the full cache available, uses compact representatives where they are sufficient, and retrieves exact entries where the current query needs more detail. The next question is how to make that choice without first reading every key.

Method Overview

Summarize the cache once, estimate each cluster’s risk, and refine the clusters that need exact KV entries.

The selection step reads cached cluster summaries. Only clusters that need refinement fetch their original KV entries; the others contribute through size-weighted representatives. The animation follows one query through this process.

1. Summarize. Partition the KV cache into contiguous clusters and cache their mean keys, mean values, and metadata.

2. Select. Score each cluster using the query-dependent attention-error bound: global importance × local distortion.

3. Refine. Expand clusters with RC > τ and attend to the resulting mixed representation.

The full original KV cache remains available. RefineKV reduces decoding reads and computation; τ controls local approximation risk.

Why a Risk Score?

Attention mass alone does not tell us whether a cluster can be replaced by its mean. We also need to know how differently its keys respond to the current query. Computing the exact approximation error would require the full KV entries—the reads we are trying to save.

RefineKV instead derives an upper bound on attention-output error and uses its cluster-wise terms as risk scores. Each score combines two factors that can be estimated from cached summaries:

Global importance

The cluster’s approximate share of attention mass. An error in a more influential cluster can have a larger effect on the output.

Local distortion

A bound on how far individual QK logits can deviate from the representative’s logit under the current query. Similar responses are easier to approximate.

RC > τ → expand to exact KV entries · RC ≤ τ → use the representative

The trade-off creates the curved decision boundary below: more important clusters tolerate less distortion. τ is a per-cluster selection threshold, rather than a direct bound on the final generated answer’s error.

Scatter axes fit each sample by default; select Shared to compare samples on identical axes. Color scales and the QK score axis remain shared in both views. Switching samples preserves τ. Within each sample, Q, K, the cluster summaries, and each risk score stay fixed as τ changes. The selected boundary is the level set RC = τ. As in the Figure 2 plotting code, this slice uses Vmax for both value-bound terms:

RC = 2 p̂C Vmax [(cosh δC − 1) / D + tanh(δC / 2)]
D = ΣC′ p̂C′ cosh δC′

δC on this plot is a bound on logit deviation, not the empirical variance of the 10 displayed scores. Point color records the original single-cluster replacement error: ‖o − o′C‖₂ with all other clusters exact. It is not recomputed as a total error for the selected τ.

Does Higher Risk Predict Larger Error?

Figure 2’s right panels compare RC with the measured error in a cluster’s attention contribution. Across 4,124 observations per model, Spearman rank correlation is 0.945 for Llama and 0.947 for Qwen. Values close to 1 mean that clusters ranked as riskier also tend to have larger approximation errors.

Figure 2 (right), replotted from the original data: WikiText-2, layer 15, four query heads and 16 query positions per model; clusters with at least two keys. Both panels share log scales. The error here is ‖oC − ôC‖₂ for a cluster’s attention contribution; the interactive view above reports single-cluster replacement error with other clusters exact.

This agreement supports using the score to prioritize which clusters to expand. Correlation measures the quality of that ranking; the decoding demo and benchmark results show how the resulting access decisions translate into speed and task quality.

How this demo was measured +

This replay uses real token-arrival timestamps from a LongBench-v2 literary-QA prompt: 130,801 input tokens and 256 output tokens. Both methods run sequentially on the same NVIDIA RTX PRO 6000 Blackwell GPU, using BF16 and vLLM 0.31.0.

Each method has one warmup and three measured runs; the video shows the median-TPOT run for each, aligned at the first output token. Playback is at 0.5× speed; prefill is excluded. RefineKV uses ε = 0.01 and GQA-mean. At 3.20 seconds of decode time, RefineKV has produced 256 tokens and Full Attention 140.

Evaluation

Quality–latency trade-offs on LongBench, RULER, and HELMET, using Llama-3.1-8B-Instruct and Qwen2.5-7B-Instruct.

Read Figure 4 toward the upper left: higher task score with less time per output token is better. Varying τ traces RefineKV’s quality–latency trade-off; Table 1 breaks down representative operating points by task group.

At τ = 0.01, RefineKV retains near-full-attention quality while achieving up to 11.7× attention-phase acceleration and 1.76× faster decoding. The access pattern adapts to each query instead of following a fixed KV budget.

A more aggressive threshold, τ = 0.1, reaches up to 1.82× decode speedup in the paper, with quality effects that vary by task.
